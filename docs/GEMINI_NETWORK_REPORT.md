# Vercel → Google API 네트워크 비교 측정

측정: 2026-11-17, Vercel region `iad1`, 서버 설정 모델 `gemini-3.8-flash`.

실제 키를 서버 밖으로 꺼내지 않고 관리자 전용 `gemini-network` 검사로 동일 Google API 호스트에 새 TLS 연결을 각각 만들었습니다. 인증 없는 GET/POST, 인증 모델 조회, 고정 '안녕' 생성 1회를 비교했습니다. 생성 요청은 기존 Redis Gemini 일일 한도를 공유하고 결과를 120초 캐시합니다. 자동 재시도와 Apify Actor 실행은 없습니다.

아래 밀리초는 각 요청 시작부터의 **누적 경과 시간**입니다. DNS/TCP/TLS 각각의 독립 소요 시간이 아닙니다.

| 요청 | DNS 완료 | TCP 연결 | TLS 완료 | 요청 전송 완료 | 첫 응답 | HTTP |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 인증 없는 모델 목록 GET | 10 | 12 | 17 | 18 | 28 | 403 |
| 인증 없는 생성 POST | 5 | 8 | 16 | 18 | 26 | 403 |
| 키 포함 모델 메타데이터 GET | 4 | 7 | 16 | 16 | 84 | 200 |
| 키 포함 최소 생성 POST | 2 | 4 | 10 | 10 | 5650 | 503 |

전체 관리자 검사 요청의 클라이언트 경과 시간은 6.51초였습니다. 로컬 실행 환경의 인증 없는 GET 대조 요청도 TLS 약 0.038초, 첫 응답 약 0.213초, HTTP 403으로 완료됐습니다. 로컬 대조는 같은 API 키로 인증한 생성 요청이 아니므로 인증 생성의 환경 간 완전한 비교로 취급하지 않습니다.

## 결론과 한계

이번 측정에서는 Vercel의 기본 DNS/TCP/TLS 연결과 POST 전송에 장시간 지연이 없었습니다. 같은 호스트에서 인증된 모델 조회도 성공했고, 최소 생성 요청은 연결 후 Google API로부터 HTTP 503을 받았습니다. 따라서 관측된 실패는 단순 DNS/TCP/TLS 연결 불능보다 **Google 생성 엔드포인트의 서버/게이트웨이 오류 응답** 쪽으로 좁혀집니다.

Google 내부의 큐·모델 용량·게이트웨이·프로젝트 처리 중 정확히 어느 부분인지는 외부 단계별 시간과 HTTP 상태만으로 알 수 없습니다. 이 결과만으로 모든 네트워크 문제를 영구 배제하거나 Google 전체 장애로 단정하지 않습니다. 요청 전송 완료 이벤트는 로컬 요청 스트림 종료이며 Google의 수신 확인은 아닙니다. 다만 실제 HTTPS 응답 503까지 수신했습니다.

Gemini 생성 성공으로 보고하지 않습니다. 기존 JSON 요청의 temperature·직렬 대기 수정은 별개 개선이며, 이번 최소 요청의 503을 그 수정만으로 해결하지 못했습니다. 코드/Mock 테스트 92개와 Windows/Linux × Node 20/22 CI는 통과했습니다.
