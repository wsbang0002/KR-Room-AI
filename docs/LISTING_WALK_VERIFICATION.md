# 실배포 검증안 · 매물에서 캠퍼스까지의 도보 시간

검증 대상은 로그인한 사용자가 실제 매물 카드에서 확인하는 TMAP 보행 경로다. 이 문서는 실행 절차이며 이번 배포의 실측 결과는 아직 없다. 공개 역에서 캠퍼스까지 조회한 기록은 별도 기능의 증거로 관리한다.

## 준비

1. Vercel에서 운영 도메인에 연결된 Production 배포의 Git 커밋과 검사 시작 시각(한국시간)을 기록한다. 운영 상태에서 `walking.enabled`, `walking.keyConfigured`, `redisConfigured`가 모두 `true`인지 확인하고 `walking.cacheAllowed`, `walking.dailyLimit`, `walking.maxPerSearch` 값을 적는다. [운영 상태](https://kr-room-ai.vercel.app/api/status)
2. SK 대시보드에서 해당 앱의 무료 경로안내 상품과 남은 일일 제공량을 확인한다. 카드 검사에는 TMAP 신규 시도 최대 1건을 사용한다. 아래 자동 검색 검사는 별도이며 검색당 최대 5건을 사용할 수 있다. 신규 매물 수집은 이 검사에 필요하지 않다. [TMAP 운영 기준](TMAP.md)
3. 운영 사이트에서 **로그인**한 뒤 보유 지역에 실제 매물이 있는지 확인한다. 브라우저 개발자 도구의 Network에서 같은 사이트의 `/api/search`와 `/api/routes/walking` 요청·응답을 확인할 수 있게 한다. 공유 기록에는 로그인 키, 쿠키, 요청 헤더, 정확한 주소·좌표, HAR 파일을 넣지 않는다. [운영 사이트](https://kr-room-ai.vercel.app/)

## 필수 · 카드에서 실매물 1건 확인

1. 이전 검색 조건이 남아 있으면 **조건 초기화**를 누른다. 목적지와 시간 제한을 빼고 보유 지역을 검색한다. 예를 들어 무실동에 매물이 있으면 `원주시 무실동 원룸`을 입력한다. 좌표가 있는 카드 한 장을 고르고, 검색 응답에서 그 매물의 `id`를 확인한다. 해당 지역에 후보가 없으면 보유 지역 목록에서 다른 지역을 선택한다. 후보를 확보하지 못하면 ‘검증 보류 · 대상 매물 없음’으로 기록한다.
2. 원주시 매물 카드의 **강원대 원주캠퍼스까지 도보**를 한 번 누른다. **목적지 찾기**를 이용할 때는 `강원대학교 원주캠퍼스`를 찾아 주소를 확인하고 선택한다. 카드가 보낸 `POST /api/routes/walking`의 `listingId`가 앞에서 선택한 매물 ID와 일치하고, `destinationId`가 `knu-wonju`인지 확인한다. 공개 장소 폼의 요청은 `publicOriginId`를 사용한다.
3. HTTP 200과 함께 응답 본문의 `status=success`, `validation=verified`, `mode=walking`, `provider=tmap` 및 두 ID의 일치를 확인한다. 서로 떨어진 두 지점에서 `distanceMeters`와 `durationSeconds`는 양수이고, `durationMinutes`는 `durationSeconds / 60`을 올림한 값이어야 한다. `calculatedAt`도 확인한다.
4. 선택한 카드에서 **도보 예상 N분 · M m**, 목적지 이름, TMAP 보행 경로, 계산 시각이 응답과 일치하는지 확인한다. `originApproximate=true`이면 **대략적 매물 위치 기준**이 표시되어야 한다. 다른 카드가 있다면 그 카드의 표시가 그대로인지 확인한다.

**통과 기준**은 동일 매물·동일 목적지의 응답과 카드가 일치하고 `cacheHit=false`인 것이다. `cacheHit=true`이면 ‘기존 경로 표시 확인’만 기록하고 신규 TMAP 호출은 미검증으로 남긴다. 경로 캐시를 지우거나 같은 버튼을 반복해서 누를 필요는 없다.

## 별도 · 자연어 검색에서 자동 계산 확인

신규 시도 여유가 있을 때 조건을 초기화하고 보유 지역과 목적지를 모두 명시한다. 예를 들어 `원주시 무실동 원룸에서 강원대학교 원주캠퍼스까지 도보 시간 알려줘`를 검색한다. 화면의 검색 지역이 무실동인지, 도착지가 원주캠퍼스인지 먼저 확인한다.

- **자동 계산 대상**은 원본 마지막 관측일(유효한 값이 없으면 수집일)이 검사 시점으로부터 7일 이내이고, 좌표와 나머지 검색 조건이 확인된 매물이다. 지역 보유 건수에는 오래된 매물도 포함될 수 있으므로 각 매물의 `syncStatus`를 확인한다. 보유 매물이 모두 `stale` 또는 `unknown`이면 `walking.selectedCount=0`, `walking.status=no-eligible-listings`가 예상된다. ‘자동 계산 보류 · 최근 확인된 후보 없음’으로 기록하고 TMAP 장애로 집계하지 않는다.
- **시간 상한 없는 검색**에서는 `/api/search` 응답의 `walking.selectedCount`가 배포의 `maxPerSearch` 이하이고, `walking.successCount`가 1 이상이면 성공한 매물의 `walkingRoute`와 카드의 분·거리를 대조한다. 각 경로의 `listingId`는 그 카드의 매물 ID와 같아야 한다. 자동 검색은 서버에서 경로를 계산하므로 브라우저에는 개별 경로 POST가 보이지 않을 수 있다.
- **15분 제한**까지 검증할 때는 남은 호출량을 다시 확인하고 같은 지역·목적지에서 `도보 15분 이내`를 추가한다. 조건 충족 목록의 매물은 모두 확인된 도보 시간이 15분 이하여야 한다. 정상 계산한 후보가 전부 15분을 초과했다면 조건 충족 0건도 정상이다. 시간을 구하지 못한 후보에는 미확인 안내가 필요하다. 실제 자료에 경계값이 없으면 15분/16분의 분류는 `test/walking-search.test.js`의 모의 테스트 결과로 구분해 기록한다.

## 보류·실패 판정과 증거

| 관측 | 판정과 후속 확인 |
| --- | --- |
| 로그인이 풀렸거나 HTTP 401 | 세션을 확인한다. 인증에 실패한 실행에서는 매물 경로를 검증할 수 없다. |
| `status=unconfirmed` | 본문의 `reason`을 기록한다. 예를 들어 `invalid-origin`은 출발 좌표, `redis-unavailable`은 한도 예약, `daily-limit`은 당일 앱 한도, `upstream-rate-limit`은 공급자 한도를 확인한다. 숫자 시간이 표시되면 표시 오류다. |
| ID 불일치, 카드와 API의 분·거리 불일치 또는 다른 카드가 함께 갱신됨 | 카드 검증 실패. 당시 배포 커밋과 어느 필드가 달랐는지 기록한다. |

검사 후 기록 형식은 `배포 커밋 / KST / 카드 또는 자동 검색 / 매물 별칭 / 목적지 ID / HTTP·status·reason / cacheHit / 응답·화면 일치 여부 / 통과·보류·실패`로 한다. 시간·거리 수치는 화면에서 대조하고 장기 보관할 기록에는 일치 여부만 남긴다. 카드 검증과 자동 검색 검증은 각각 판정한다. 배포 직후 잘못된 매물의 시간이 표시되면 해당 배포의 검증을 실패로 기록하고, 운영자가 이전 정상 배포 복구 또는 보행 경로 일시 중지를 결정한다.
